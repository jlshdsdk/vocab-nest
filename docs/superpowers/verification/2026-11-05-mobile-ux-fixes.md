# 手机学习体验修复与客户路径复测

## 用户报告与根因

1. 发音延迟：旧点击路径内初始化系统音色；未优先本地音色，待播放时的快速重复点击又取消重启队列。原来仅检查 speak 被调用，没有验证用户点击处理时间。
2. 辨析释义不足：数据只有 word / note，显示辨析说明不能替代原词和关联词的独立释义。
3. 切词／标记抖动：标记重建整卡、丢失焦点和 details 状态；切词每次触发进场动画，并无条件 scrollIntoView。顶部切词复现 scrollY 从 0 跳到 218。

## 第一轮修复

- 标记仅局部改变按钮、徽标和进度点，不替换词卡或控制节点；徽标预留稳定空间。
- 去掉每次切词的横移/淡入，无条件滚动改为只在深阅读时回到新词头；手机固定学习操作条，上下词与标记都可触达。
- 切词只写阅读位置所在的元数据，不重写完整学习事件日志。
- 系统音色在词组空闲期预备，按同口音优先本地音色；首次播放仍在用户手势同步调用栈中。重复待播放点击不重启，切词停止前词，提供准备/播放/错误及超时反馈。不能保证所有真实设备音频硬件都没有固有启动延迟。
- 按组补充双方释义：原词库优先，其余来源为 MIT 许可 ECDICT 与明确标注的短语/拼写提示。8,042 个选定词形、13,099 条关联全部覆盖，原始词库文件未修改。
- 每组补充数据平均约 11.4KB、最大约 14.9KB；首页不下载完整大词典。收藏页、备份和导出保留双方释义；旧收藏不改变身份键。

## 第二轮客户操作复测

按首页→词组→发音→标记→连续切词→展开辨析→收藏→列表→三类自测→设置大字/月白→刷新/旧缓存/离线的顺序操作。

另外发现并修复：

- 跨词重置展开偏好：阅读者收起近形辨析、展开用法后，下一词不应反着恢复默认。新增失败回归后保留本次阅读会话偏好。
- 列表末尾进入词条保留旧滚动：词头曾位于视口上方约 1297px。只在列表跳转时定位到所选词头，普通标记不滚动。
- 短视口中固定操作条可能影响点击命中；增加阅读安全滚动间距，在测试中确认实际点击的是发音按钮，而非其下面的标记按钮。

## 证据和界限

本轮最终全套：node --test --test-reporter=spec tests/*.test.cjs，89 tests，89 pass，0 fail，0 skipped。所有修改后 JS 的 node --check 和 git diff --check 通过。

关键旧失败均保留为回归：卡片/按钮节点、焦点、展开状态、滚动偏移与高度不变；顶部切词不跳；控制目标在底栏上方；真实旧 worker 升级与离线；双方释义全覆盖与收藏刷新；首次 UK 发音同步用户手势。

慢音色冷启动边界测试中，旧点击处理阻塞约 181ms；新预备后点击处理实测约 1.4ms，选择本地 British 测试音色。此数字衡量应用点击处理路径，不是对真实手机“发声只需 1.4ms”的承诺。

操作截图、录像与逐项记录保留在本地 output/mobile-ux-debug，未部署用户级本地目录或调试录音。第二轮录像成功保存；首次录像封装命令曾报错，仍保留原文件。

## 独立审查及最后修复

独立只读审查对候选 09711c9 给出 2 项 Important、0 项 Critical：词组内容已载入会阻止缺失释义重新下载；切学习模式与会话前进遗漏停止语音。两项均用真实浏览器先复现失败，再修复，专项和全套回归转绿；收藏和导出不保存“释义缺失”占位文本。

客户复测还发现 360×740 复习区高 151px，挡住例句。改成 76px 的紧凑评分/朗读区，评分标签分行；复测例句底部约 528px、操作区从 590px 开始，互不遮挡。

审查未能证明的部分继续保留边界：真实手机的声音硬件/系统键盘、8,042 个词典条目逐条独立语义复核，以及生产发布（须另做线上验证）。本轮不把“全库字段覆盖”声称为每条人工校对，也不把交互测试声称为所有设备绝对零延迟。

最终客户端缓存版本：vocab-nest-selene-20261105-ux3。既有的最终 Lighthouse 性能分差距未以这轮交互修复冒充解决。
